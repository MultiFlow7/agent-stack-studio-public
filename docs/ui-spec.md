# 界面与交互规格

## 1. 设计方向

产品气质是克制、清晰、可信。使用者通常在办公室或研究环境中的 Mac 上长时间查看配置、差异和实验结果，因此第一版采用高可读性的浅色产品界面，保持信息密度，但不使用装饰性数据卡片或大面积动画。

Multica 提供交互参考：Agent 列表进入详情，详情通过清楚的分区和页签管理。Studio 不复制 Multica 的代码、品牌资产和具体视觉表现。

## 2. 应用框架

窗口由三个稳定区域组成：

- 顶部栏：当前工作区、全局搜索、运行状态和应用级操作。
- 一级侧栏：Agent、组件、实验、运行、设置。
- 内容区：列表、详情或编辑流程。

应用记住窗口大小、侧栏状态和最后访问位置。首次启动直接进入 Agent 空状态，不要求注册团队账号。

## 3. Agent 列表

### 主要信息

- 名称与描述。
- 当前版本和草稿状态。
- 执行模式：Agent Loop、Workflow、Hybrid 或 External Harness。
- Stack 就绪状态。
- 最近运行时间和结果。
- Multica 发布状态。

### 主要操作

- 创建 Agent。
- 从本地目录导入。
- 打开 Agent。
- 复制为新 Agent。
- 归档，默认不提供永久删除入口。

空状态需要解释两条开始路径：“创建空白 Agent”和“导入本地项目”。

## 4. Agent 详情

详情页顶部固定显示名称、当前版本、Stack 状态和主要操作。页签包括概览、Stack、能力、实验、运行和设置。

### 概览

展示用途、执行模式、当前版本、组件数量、未解决问题、最近运行和发布状态。数字用于状态摘要，不做营销式指标卡。

### Stack

这是核心编辑页面。按执行控制、模型与策略、上下文与记忆、工具与环境、观测与评价分组显示能力槽位。

每个槽位显示：

- 当前 Owner。
- 来源组件和版本。
- 内置、可配置、需要 Adapter、锁定或未知状态。
- 依赖数量与预检结果。
- 是否被当前实验锁定。

点击槽位在同一页面展开候选实现和影响范围。优先使用内联展开或右侧检查面板，不把每次选择都放入模态框。

### 能力

面向非技术用户展示指令、Skills、MCP、工具、知识和权限。此处说明 Agent 能做什么；Stack 页面说明这些能力由什么实现。

### 实验

展示基于该 Agent 创建的实验、变量、进度和主要结果。创建实验时自动使用当前 Agent Version 作为基准，不绑定可变草稿。

### 运行

展示本地运行状态、变量组合、耗时、结果、Drift 和失败原因。用户可以取消正在运行的任务，不能修改历史 Run。

### 设置

管理名称、说明、本地目录、环境声明、密钥引用、导入规则和 Multica 映射。高风险权限和高级字段放在明确分区中。

## 5. 组件页面

默认采用可筛选表格，不采用同尺寸卡片墙。列包含组件、版本、来源、能力覆盖、兼容状态、被哪些 Agent 使用和最近验证时间。

组件详情显示：

- Manifest 和来源证据。
- 提供及依赖的能力。
- 可替换等级。
- Adapter、Fork 和补丁状态。
- 配置 schema 和敏感字段。
- 契约测试与最小运行验证结果。
- 受影响的 Agent Version。

“已生成 Adapter”和“已验证兼容”必须使用不同状态和文案。

## 6. 冲突解决

冲突页或检查面板需要并排比较候选 Owner：

| 信息 | X | Y |
| --- | --- | --- |
| 覆盖能力 | A、B、C、D | C、D、E、F、G |
| 当前选择 | C Owner | D Owner |
| 替换成本 | 配置 | Adapter |
| 依赖影响 | 2 项 | 4 项 |
| 验证状态 | 已通过 | 待验证 |

选择 Owner 后立即更新影响预览，但只有通过预检才能保存为可运行版本。任何隐式副作用都以阻断状态显示，不能只显示警告后继续。

## 7. 实验页面

实验创建采用连续页面而非多层弹窗：

1. 选择基准 Agent Version。
2. 查看并锁定控制变量。
3. 选择实验变量和值域。
4. 设置数据集、重复次数和评价方法。
5. 检查矩阵、预计运行数和 Drift 规则。
6. 保存实验并开始运行。

实验详情由定义、运行矩阵、比较结果和复现信息四个视图构成。矩阵中必须能看到失败、取消、漂移和部分完成状态。

## 8. Multica 发布

发布入口位于 Agent 详情的主要操作区。发布面板展示目标 Agent、版本、包含内容、排除内容、权限要求和预检结果。

按钮使用明确文案，例如“发布此版本到 Multica”，不能使用“确定”。发布成功后提供远端标识和时间；失败时保留本地版本不变。

## 9. 状态系统

所有状态由图标、文字和颜色共同表达：

- 就绪。
- 草稿。
- 有冲突。
- 需要 Adapter。
- 验证中。
- 已验证。
- 运行中。
- 已失败。
- 已取消。
- 已发布。

全局状态词保持一致，不能在不同页面用多个近义词表达同一状态。

## 10. 键盘与可访问性

- 全部主要导航和表格行可通过键盘访问。
- 焦点顺序符合视觉顺序，焦点样式始终可见。
- 表格支持语义化表头，排序状态可被辅助技术识别。
- 表单错误靠近字段显示，并提供页面级错误摘要。
- 图标按钮必须有可读名称。
- 正文对比度至少 4.5:1，大字号至少 3:1。
- 动画只用于状态反馈，通常为 150 至 250 毫秒。
- 系统启用减少动态效果时，取消非必要移动和过渡。

## 11. 必须覆盖的界面状态

每个数据页面都必须设计：加载、空、部分数据、失败、无权限或不可执行、离线远端连接、取消中和成功反馈。加载优先使用保持布局稳定的骨架，不让中央 Spinner 替代整个内容区。

## 12. 第一版不确定项

具体字体、OKLCH 色值、间距 Token 和组件视觉规范在 UI 工程建立后写入 `DESIGN.md`。在此之前，以本文件的结构和交互约束为准，不能自行引入与“克制、清晰、可信”冲突的视觉方向。

## 13. M6 设置与恢复交互

- 一级“设置”导航在 M6 启用，可通过侧边栏或 macOS `Command+,` 进入。
- 备份和恢复均使用连续页面，只有原生文件夹选择器使用系统对话框。
- 恢复选择后先展示备份时间、来源应用版本、schema 及迁移目标、文件数和容量。只有完整性检查通过且用户勾选替换确认后，“恢复备份并重启”才可执行。
- 备份成功、预检失败、需要迁移、正在恢复和即将重启都有文字状态，不仅依赖颜色或图标。
- 页面明确说明 Keychain 密钥原文、日志与符号链接不进入备份，恢复不会伪造或移植 Keychain 密钥。

## 14. M7 Studio 项目交互

- 一级导航增加“Studio 项目”。空状态同时提供创建与打开 `.agent-stack`，并显示 CLI 的可发现路径。
- 项目页展示 revision、来源证据、Git 状态、Descriptor、Stack、Owner、验证问题和不可变版本；静态结论不得伪装为运行验证。
- 组件导入、Descriptor 更正、加入/移除、归档、删除、Owner 和冻结都支持键盘。永久删除采用内联二次确认，历史引用会给出归档或移除建议。
- 外部 CLI 修改触发重新读取并显示 revision 刷新提示；revision 冲突保留当前磁盘状态并提供“重新读取”。
- 新安装的组件目录为空。设置页的“加载演示数据”是主动操作，并明确标注“不调用真实服务”。

## 15. M8 来源发现交互

- 一级导航增加“发现”。首次进入先解释只读取公开元数据、不发送项目数据、不下载和不执行代码，再由用户提交搜索。
- 搜索栏包含查询、排序和明确的“搜索来源”按钮。加载期间保持结果区域尺寸稳定，并提供按钮和 Escape 键取消。
- 结果使用连续列表，不使用卡片墙。每项显示仓库、描述、Star、Fork、语言、许可证、提交时间、Fork 与归档状态，并注明这些字段由 GitHub 报告。
- 选择候选来源后内联展开下载交接，分别显示 clone 与静态检查参数、执行前审阅提示、复制命令、复制 JSON 和打开 GitHub 仓库。
- Studio 不提供“立即下载”或“运行仓库”按钮。网络失败、频率限制、取消、无结果、仓库不可用和复制失败均有文字状态与恢复操作。

## 16. M10 项目完整性交互

- Studio 项目页在 revision、组件数和版本数旁展示共享 Core 返回的 SHA-256 审计状态与已检查版本数。
- 从最后有效备份恢复时使用 `role="alert"` 的明确提示，说明无效原文件已保留为 `.agent-stack.invalid-*`，用户应人工比较后再继续。
- 外部编辑导致完整性失败时保留当前可见状态并显示加载/刷新错误，不把旧状态继续标为已验证。
- 哈希文案只使用“快照一致性已验证”，不得使用“已签名”“来源可信”或“作者已认证”。

## 17. M11 Keychain 与发布就绪交互

- Agent 设置中的密钥引用使用连续列表和内联元数据表单，不使用嵌套卡片。密钥原文只在 Main 调起的 macOS 原生隐藏输入对话框中填写。
- 每条引用显示用途、账户、服务和“已配置/本机缺失”文字状态；不能展示密钥原文或可读回控件。
- 写入支持相同账户幂等替换。永久移除必须先显示内联确认，并提供取消与焦点可达路径。
- 页面覆盖加载、空、失败、恢复后缺失、写入中、成功和删除失败；错误说明登录钥匙串解锁与访问建议。
- 打包应用截图验收至少包含中文设置页、应用正式图标和可见焦点路径。

## 18. M12 本地运行与能力交互

- Run 启动区在选择 Agent 后显示当前执行模式、内置 Profile 的自然语言说明，以及“导入仓库仍只做静态检查”的边界。
- Run 详情把模式翻译为中文，并展示 Workflow Version、handoff、Controller Service 或可信 Harness 绑定；完整 Manifest 仍可展开检查。
- Agent 能力页使用连续列表展示能力名称、稳定标识、当前 Owner、实现、验证等级和可展开 Provider，不使用卡片墙。
- 能力页覆盖加载、空、失败重试、就绪与阻断状态。阻断项直接使用 Runtime Plan 编译结果，并提供前往 Stack 的键盘可达操作。

## 19. M13 Agent 生命周期交互

- Agent 详情头部提供“复制 Agent”和“归档”。复制成功回到现有列表，并明确说明历史记录没有复制；归档成功从现有列表移除，但历史仍可追溯。
- Agent 列表提供“查看已归档”切换。归档空状态解释归档不会删除历史，并提供返回现有列表的键盘路径。
- 归档 Agent 详情保留历史页签，只提供恢复和永久删除生命周期操作，不提供创建 Version 或发布入口。
- 永久删除使用页面内确认区，初始焦点落在“取消”；文案列出不可逆范围。存在 Version、Run、Experiment、Receipt、映射或 Keychain 引用时显示具体阻断并保持归档。
- 生命周期操作覆盖加载、成功、失败、取消、历史冲突与键盘 Enter 路径；最终 `.app` E2E 同时验证无历史副本可删除和有历史原件被阻断后可恢复。

## 20. M14 Studio 项目双入口交互

- 通过 `--project` 启动时仍进入标准应用壳，用户主动进入“Studio 项目”后看到同一项目名、路径、revision 和 CLI 路径。
- CLI 或其他编辑器修改时，页面显示“界面已刷新到 revision N”，同时清除与新状态矛盾的旧成功反馈。
- 外部导入的组件仍只显示静态证据。GUI 加入/移出 Stack 与 CLI 命令使用同一按钮、空状态、Owner 和验证表达。
- 打包截图必须同时显示最终 revision、外部刷新提示、组件证据和当前 Stack 空/非空事实。

## 21. M17 界面偏好交互

- 侧栏顶部提供有文字与可访问名称的收起/展开按钮；收起后保留全部一级图标、焦点和 `aria-label`。
- 普通启动恢复最后一级页面；打包截图 hash、Agent 深链接或其他显式启动位置优先，不被偏好覆盖。
- 偏好读取或写入失败时保留当前可用界面，在主内容顶部显示可关闭的错误，不把业务数据误报为丢失。
- 打包 E2E 从键盘收起侧栏、进入设置并重载 Renderer，必须恢复设置页和收起状态。

## 22. M18 可移植包导出交互

- Studio 项目页头部提供键盘可达的“导出项目包”，使用 macOS 原生 Save Dialog，不在 Renderer 中接收或拼接路径。
- 页面在操作前始终说明包保留的项目事实，以及 Keychain、SQLite、Run/Experiment、Receipt、Artifact、日志和绝对路径排除边界。
- 成功状态显示目标和缩写 SHA-256；取消明确说明项目未变；便携性审计或 I/O 失败使用 `role="alert"` 并保留“重新读取”恢复路径。
- 打包 E2E 在含静态导入组件的 revision 上由 GUI 与包内 CLI 分别导出，必须逐字比较一致并保存中文成功截图。

## 23. M19 Agent 状态交互

- Agent 列表保持单一连续列表。每行依次显示身份、执行模式、版本/草稿、Stack 组件/问题、最近 Run 和发布，不拆成营销式指标卡。
- 详情标题下方显示草稿 revision、当前版本和 Stack 状态；允许换行但不得挤压名称或主要操作。
- 概览的“当前结构”连续定义列表显示组件、Owner、未解决问题、最近 Run、最近 Experiment 与发布。时间使用本机中文区域格式，状态同时有文字而不只依赖颜色。
- Run、Experiment 或 Publish 页面产生新事实后，再进入概览或返回列表必须刷新；加载失败沿用页面级错误与重试，不把旧状态继续标成当前。

## 24. M20 组件目录与详情交互

- 目录上方使用连续筛选条，包含搜索、兼容状态和来源；无结果保留“清除筛选”，不误用全局空状态。
- 组件名称是键盘可达的详情入口。详情在同一页面连续展开并接收焦点，提供“返回组件目录”，不用模态框或嵌套卡片墙。
- 目录列固定表达组件、版本、来源、能力覆盖、兼容、使用方和最近验证记录；表格可横向滚动，不在窄窗口压碎 Contract ID。
- 详情按 Manifest/来源、Adapter/Fork、能力/依赖、测试证据、使用方/受影响版本分区。缺依赖、缺证据、无使用方和无历史版本必须显示明确空文案。
- 加载、目录空、筛选空、目录失败、详情加载、详情失败/重试、成功和完整键盘打开路径都有自动化证据。

## 25. M21 Workflow DAG 交互

- Studio 项目页使用一个连续 Workflow 区域，不提供通用画布。空状态说明结构化定义与不可变版本边界，并提供“新建 Workflow”。
- 创建、添加节点和添加连线都在当前页面内联展开，提供明确保存/取消。节点类型和引用字段随结构化类型变化，子 Workflow 只列出已冻结 Version。
- 只读 DAG 图示以键盘可达的节点序列与显式有向边表达；删除节点同时删除草稿连线，但历史 Version 不变。
- 自环、回边、revision 冲突和无效引用使用页面级 `role="alert"`，保留当前图并提供重新读取；外部 CLI 修改沿用 revision 刷新提示。
- 最终 `.app` 由包内 CLI 创建/冻结 DAG，GUI 读取后故意提交回边并截图，再由 GUI 删除边、CLI 复核并恢复，证明双向一致。

## 26. M22 Adapter/Fork 任务与 Component 删除交互

- Agent 能力页和 Studio 项目页使用同一个连续任务区，逐项显示 Adapter/Fork 工作产物、契约测试、最小运行验证及“已有证据/待完成”文字状态。
- 每项任务的验收条件可由键盘展开；任务区明确说明 Studio 不自动生成、加载或执行第三方代码，不能只用颜色表达完成状态。
- Component 永久删除使用当前行内的“确认删除/取消”，不弹出脱离上下文的模态框。取消必须零写入；成功后显示 `role=status` 反馈并立即更新组件计数。
- 归档、删除、冲突和历史引用失败都保留项目上下文。错误通过 `role=alert` 显示，不泄漏 Electron IPC 内部前缀。

## 27. M23 Run 历史交互

- Run 列表增加总耗时列，终态行只提供“查看”；只有活动 Run 保留取消操作。
- 详情先显示终态和失败原因，再以连续只读区域展示 Prompt、随机种子、超时、重试/并发、总耗时和 Drift Check。
- Experiment Run 显示实验、Prompt 变量序号、重复次数和每条非预期变化；独立 Run 明确说明没有锁定实验基准，Drift 不适用。
- 超时、失败和成功历史使用同一信息结构；错误以文字和图标共同表达，长 Prompt 与 Drift 说明允许换行。
- 500ms 与 1s 选项用于可验证的本地短超时流程，仍走真实 Runtime 取消与清理，不引入测试专用开关。

## 28. M24 实验矩阵交互

- 实验详情顶部以连续证据区显示状态、计划/终态、成功/需关注、终态成功率、成功平均耗时和复现定义；部分完成时分母始终保留。
- 矩阵工具栏提供文本搜索与“全部/进行中/成功/需关注”状态范围。结果数量使用 `aria-live`，清除筛选可由键盘到达。
- 失败、取消和 Drift 阻断使用文字状态与原因共同表达，不依赖颜色。筛选无结果时保留恢复操作。
- 矩阵与基础对比都是只读历史视图；取消中的实验仍走既有确认路径，筛选不会改变实验事实。
- 基础对比明确写出第一个 Prompt/seed 是基准；无成功样本时耗时与相对基线显示 `—`，不暗示不存在的统计结论。

## 29. M25 来源发现状态与恢复

- 首次进入持续显示“仅公开元数据 / 不下载，不执行代码”，搜索框自动聚焦且完整键盘可达。
- 输入不足两个字符时显示“搜索条件不完整”，明确没有发送网络请求；“修改搜索条件”把焦点送回原输入框，不重复无效请求。
- 离线、15 秒超时、频率限制和一般 Provider 错误使用不同标题、说明和恢复建议；可重试状态保留原查询。
- 加载使用 `aria-busy` 和可见取消按钮，Escape 也能取消；取消后说明没有保存结果或下载仓库并提供重新搜索。
- 成功无结果与首次空闲使用不同文案；有结果继续显示 Provider 报告事实、额度和分页。任何错误都不得泄漏 Electron IPC 内部前缀。

## 30. M26 工作区命令中心交互

- 顶栏左侧显示真实项目名称、revision 与项目状态；点击进入 Studio 项目。没有项目时明确写“未打开项目”，不得伪造默认项目。
- 顶栏中部提供 `⌘K` 搜索，右侧显示最近或活动 Run 状态并直达历史，另有图标和可访问名称完整的“创建 Agent”操作。
- 命令面板使用一个搜索输入和连续结果列表，显示导航、操作、项目、Agent、组件、Run 与实验类别；上下箭头选择、Enter 打开、Escape 关闭、Tab 保持在对话框内。
- 加载、无结果和错误状态占用同一结果区域并通过 `aria-live`/`role=alert` 表达；失败只影响命令中心，不覆盖当前业务页面。
- 页面间统一复用 Run、Experiment、Stack、Publish、工作区与活动状态词汇；状态颜色必须同时伴随图标、文字或可访问名称。

## 31. M27 可访问入口验收

- 一级导航固定为 Studio 项目、发现、Agent、组件、实验、运行记录和设置；全部可聚焦、未禁用，并以 `aria-current=page` 标记当前页面。
- 图标按钮必须提供可访问名称；全局搜索同时声明 `Meta+K`，视觉 `kbd` 不进入冗余按钮名称。
- 最终 `.app` 的 Accessibility Tree 必须暴露 main/navigation landmarks，所有可见按钮名称非空。
- 输入 placeholder 只能补充格式或查询示例，不能代替 label；新增提示必须进入验收分类清单。

## 32. M28 中文截图证据契约

- 截图只由最终 `.app` 黑盒流程生成，不允许用单元测试 DOM、设计稿或 mock 页面代替。
- 截图矩阵必须至少覆盖空、成功、失败、取消、冲突与外部刷新，并绑定旅程 ID 和生成器 token。
- 截图必须保留中文标题、原因、状态文字与 suggested action；颜色仍只作辅助。
- 截图固定为本地验收产物且 Git ignored，最终报告保存相对路径与 `local-only-gitignored` 发布边界。

## 33. M30 Agent-first 信息架构

- 一级导航固定为 Agent、组件库、发现、实验、运行记录和设置；“项目设置”只从顶栏当前项目入口打开。
- Agent 详情使用连续编辑区呈现能力、组件组合、Owner 冲突、兼容状态与下一步；高级 Descriptor 证据渐进展开，不使用卡片套卡片。
- 兼容状态始终用文字表达，附验证方法、时间、证据、阻断原因和 `suggestedActions`；“未检查”与“静态检查完成但机器证据不足”必须明确区分。“重新静态检查”点击后在当前详情视口内显示进行中状态，并就地公布成功、取消或失败结果；“需配置”与“需 Adapter”提供可执行修复路径。
- 顶栏必须显示当前项目、revision 和完整性；切换、外部修改刷新和 revision 冲突保留明确文字、可恢复操作与键盘路径。
- 组件库导入完成后立即刷新当前项目；Agent 组装器不再读取一套 SQLite 目录。

## 34. M31 兼容处置交互

- 组件目录与 Agent Stack 统一显示“机器证据不足”和一句缺失证据说明，禁止显示原始枚举或“待确认”。
- 兼容详情按状态/说明→证据/阻断→可执行下一步→Descriptor 表单→Receipt/Artifact/审计的连续文档层级排列。
- 结构化表单必须覆盖平台、提供/依赖能力、替换性、激活、配置、Adapter、权限、Keychain 引用和策略；动态行在输入时保持稳定焦点，错误就地呈现，Cancel 零写入。
- “验证等级”始终只读；策略旁明示“处置方向，不产生技术证据”。运行验证进度、取消、超时、失败、成功和重试在原位表达，不丢失已填写上下文。
- Component 目录提供“现有/已归档/全部”筛选。恢复是已归档详情的可见操作，成功后立即返回 Agent 选择器；永久删除在归档前不可用并解释原因。
- 全流程保持 WCAG 2.2 AA：文字+图标表达状态，焦点可见，动态列表/对话框焦点可预测，外部修改刷新与 revision 冲突都有可恢复文字路径。
